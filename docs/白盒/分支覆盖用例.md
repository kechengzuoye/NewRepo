# 判级函数 分支覆盖用例设计

> 被测对象：前端「匹配分析」页面评分列里的匹配分数判级函数（源码第 91–96 行）
> 覆盖目标：3 个判定、6 条分支全部走到；同时与流程图的四条路径对应
> 结论：4 条用例即可达成 6/6 分支覆盖；推荐 6 条，兼顾边界值与 `或` 条件的两个操作数

---

## 1 分支清单

判级函数有三个判定，每个判定有真、假两个出口，共 6 条分支：

| 分支 | 所属判定 | 取值 | 走向 | 对应路径 |
|---|---|---|---|---|
| B1 | 判定1：分数未提供？ | 真 | 返回无等级，结束 | 路径一 |
| B2 | 判定1：分数未提供？ | 假 | 进入判定2 | 路径二 / 三 / 四 |
| B3 | 判定2：分数不低于 80 分？ | 真 | 返回高匹配，结束 | 路径二 |
| B4 | 判定2：分数不低于 80 分？ | 假 | 进入判定3 | 路径三 / 四 |
| B5 | 判定3：分数不低于 60 分？ | 真 | 返回中匹配，结束 | 路径三 |
| B6 | 判定3：分数不低于 60 分？ | 假 | 返回低匹配，结束 | 路径四 |

分支覆盖的要求：B1–B6 每条至少被执行一次。

---

## 2 判定表

| 规则 | R1 | R2 | R3 | R4 |
|---|---|---|---|---|
| 分数未提供 | 是 | 否 | 否 | 否 |
| 分数不低于 80 分 | — | 是 | 否 | 否 |
| 分数不低于 60 分 | — | — | 是 | 否 |
| 动作：无等级 | ● | | | |
| 动作：高匹配 | | ● | | |
| 动作：中匹配 | | | ● | |
| 动作：低匹配 | | | | ● |
| 覆盖分支 | B1 | B2、B3 | B2、B4、B5 | B2、B4、B6 |

四条规则互斥且完备，每条规则至少一条用例即可覆盖对应分支。

---

## 3 用例设计

| 用例 | 输入 | 期望结果 | 覆盖分支 | 路径 | 设计说明 |
|---|---|---|---|---|---|
| B01 | 80 | 高匹配（绿） | B2、B3 | 路径二 | 80 分取等号，验证 `>=` 的边界 |
| B02 | 79.9 | 中匹配（琥珀） | B2、B4、B5 | 路径三 | 80 分的下沿 |
| B03 | 60 | 中匹配（琥珀） | B2、B4、B5 | 路径三 | 60 分取等号，验证 `>=` 的边界 |
| B04 | 59.9 | 低匹配（红） | B2、B4、B6 | 路径四 | 60 分的下沿 |
| B05 | 未提供 | 无等级（不染色） | B1 | 路径一 | 报告未分析完，无分数 |
| B06 | 空值 | 无等级（不染色） | B1 | 路径一 | 覆盖 `或` 的右操作数（条件口径） |

> **为什么边界值取 80 / 79.9 / 60 / 59.9：** 分支覆盖本身只要求真、假各走一次，用 95、70、40 也能满足；但取等号与下沿能同时验证判定写成了 `>=` 还是 `>`。若把 `score >= 80` 误写成 `score > 80`，B01 的 80 分就会失败；若把 `>= 60` 误写成 `> 60`，B03 会失败。

## 4 覆盖矩阵

● 表示该用例命中该分支。

| 用例 | B1 | B2 | B3 | B4 | B5 | B6 | 条件1 取真 | 条件2 取真 |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| B01 80 | | ● | ● | | | | | |
| B02 79.9 | | ● | | ● | ● | | | |
| B03 60 | | ● | | ● | ● | | | |
| B04 59.9 | | ● | | ● | | ● | | |
| B05 未提供 | ● | | | | | | ● | |
| B06 空值 | ● | | | | | | | ● |
| **覆盖** | ● | ● | ● | ● | ● | ● | ● | ● |

- 分支覆盖：6/6；
- 若改用 Istanbul / `@vitest/coverage-v8` 的口径，`或` 的左右操作数各算一条 branch，需要 B05（左操作数取真）与 B06（右操作数取真），条件分支为 4/4。

## 5 最小集与推荐集

**最小分支覆盖集：B01、B03、B04、B05（4 条）。**

| 用例 | 覆盖分支 |
|---|---|
| B01（80） | B2、B3 |
| B03（60） | B2、B4、B5 |
| B04（59.9） | B2、B4、B6 |
| B05（未提供） | B1 |

B1–B6 各至少命中一次，且 4 条用例正好覆盖流程图的 4 条路径，语句覆盖也是 7/7。这组用例的短板是条件覆盖只有 3/4——没有 `空值` 输入，`或` 的右操作数不会取真。

**推荐集：B01–B06（6 条）。** 在最小集基础上加 B02（80 下沿）和 B06（空值），分支、条件、边界三类都照顾到；这也是白盒脚本里 6 条相关用例的来源。

## 6 与已执行用例的对应关系

这 6 条设计用例都已包含在 [白盒测试脚本.mjs](白盒测试脚本.mjs) 的 12 条用例里，并被实际执行过：

| 设计用例 | 脚本中的用例 | 输入 | 执行结果 |
|---|---|---|---|
| B01 | 用例02 | 80 | 通过 |
| B02 | 用例03 | 79.9 | 通过 |
| B03 | 用例04 | 60 | 通过 |
| B04 | 用例05 | 59.9 | 通过 |
| B05 | 用例07 | 未提供 | 通过 |
| B06 | 用例08 | 空值 | 通过 |

[执行结果.txt](执行结果.txt) 中每条分支的“取真 / 取假”清单可以核对：

- 判定1 取真：用例07、用例08；取假：用例01–06、09–12；
- 判定2 取真：用例01、02、10；取假：用例03–06、09、11、12；
- 判定3 取真：用例03、04、12；取假：用例05、06、09、11。

最小集 B01/B03/B04/B05（即用例02、04、05、07）在上述清单中均有出现，因此这 4 条子集同样达成 6/6；完整 12 条只是在此基础上多了等价类与越界用例，覆盖率结论不变：**判定分支 6/6，100%**。

---

## 7 结论

1. 判级函数分支覆盖需要 6 条分支：B1–B6，分别对应“缺分 / 有分 / 高匹配 / 非高 / 中匹配 / 低匹配”；
2. 4 条用例（80、60、59.9、未提供）即可达到 6/6，且同时覆盖语句 7/7、路径 4/4；
3. 若按条件口径统计 `或` 的两个操作数，补一条空值用例（B06）即可达到 4/4；
4. 用例取 80、60 的等号值和 79.9、59.9 的下沿，是为了在覆盖分支的同时抓住 `>=` 写错成 `>` 的边界缺陷。
